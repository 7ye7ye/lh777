# 数据源切换问题修复说明

## 问题描述
应用查询时仍然使用 `jeecg-boot` 数据库而不是 `hospital` 数据库，导致 `Table 'jeecg-boot.department' doesn't exist` 错误。

## 已完成的修复

### 1. Service 层修复
- **移除类级别的 `@DS` 注解**，避免与方法级别冲突
- **在方法级别添加 `@DS("hospital")` 注解**，确保每个查询方法都使用正确的数据源
- **改用直接注入 Mapper**，使用 `departmentMapper.selectList()` 代替 `this.list()`，确保数据源切换正确传递

### 2. Mapper 层修复
- **移除 Mapper 接口上的 `@DS` 注解**，依赖包路径映射自动路由
- 包路径映射配置（`application-dev.yml`）应该自动处理 `org.jeecg.modules.hospital.mapper` 包下的所有 Mapper

### 3. 修改的文件
- `DepartmentServiceImpl.java` - Service 实现类
- `DoctorServiceImpl.java` - Service 实现类
- `DepartmentMapper.java` - Mapper 接口
- `DoctorMapper.java` - Mapper 接口
- `DepartmentAppletController.java` - 控制器（已移除类级别 @DS）
- `DoctorAppletController.java` - 控制器（已移除类级别 @DS）

## 必须执行的操作

### 1. 完全重启后端应用 ⚠️ **关键步骤**
```
1. 停止当前运行的应用（完全停止，不要只是热部署）
2. 清理编译缓存：
   - 删除 `target` 目录
   - 或者在 IDE 中执行 "Clean" 和 "Rebuild Project"
3. 重新编译项目
4. 重新启动应用
```

### 2. 验证数据源配置
确认 `application-dev.yml` 中配置正确：
```yaml
spring:
  datasource:
    dynamic:
      primary: jeecg-boot
      datasource:
        jeecg-boot: ...
        hospital: ...
      package:
        - key: org.jeecg.modules.system.mapper
          value: jeecg-boot
        - key: org.jeecg.modules.hospital.mapper
          value: hospital  # 这里确保是 hospital
```

### 3. 检查应用启动日志
启动时应该看到类似日志：
```
Dynamic DataSource initialized: [jeecg-boot, hospital]
```

## 工作原理说明

### 数据源切换优先级
1. **方法级别的 `@DS` 注解**（最高优先级）
2. **类级别的 `@DS` 注解**
3. **包路径映射**（最低优先级）

### 当前配置策略
- **Service 方法**：使用 `@DS("hospital")` 显式指定数据源（确保切换）
- **Mapper 接口**：移除 `@DS`，依赖包路径映射自动路由
- **Controller**：不添加 `@DS`，让 Service 层处理

## 如果问题仍然存在

### 检查清单
1. ✅ 应用是否完全重启（不是热部署）
2. ✅ 编译缓存是否清理
3. ✅ `@DS` 注解是否正确添加在 Service 方法上
4. ✅ Mapper 接口上的 `@DS` 是否已移除
5. ✅ 包路径映射配置是否正确
6. ✅ `hospital` 数据源的 URL、用户名、密码是否正确

### 调试方法
1. **添加日志**：在 Service 方法开始处添加日志，确认方法被调用
2. **检查数据库连接**：确认能够连接到 `hospital` 数据库
3. **检查 MyBatis 日志**：启用 SQL 日志，查看实际使用的数据源

### 可能的其他原因
- Spring AOP 代理未正确生效（检查 `@EnableAspectJAutoProxy`）
- 事务管理器配置问题（如果使用 `@Transactional`）
- 动态数据源版本兼容性问题

## 预期结果
修复后，所有对 `department` 和 `doctor` 表的查询都应该使用 `hospital` 数据库，不再出现 `Table 'jeecg-boot.department' doesn't exist` 错误。

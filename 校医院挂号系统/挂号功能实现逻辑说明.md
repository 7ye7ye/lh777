# 小程序挂号功能实现逻辑说明

## 📋 功能概览

小程序挂号功能实现了从选择医生、预约时段、支付到创建挂号记录的完整流程，支持正常挂号、候补队列、重复挂号检查等功能。

---

## 🔄 完整流程

```
选择医生 → 预约页面 → 选择挂号类型/日期/时段 → 确认预约 → 支付页面 → 支付成功 → 创建挂号记录 → 消息通知
```

function formatLocalDateTime(date) {

## 🗄️ 数据流转

### 前端 → 后端传递的数据

#### 创建挂号请求体
```javascript
{
  scheduleId: 123,              // 排班ID（必填）
  patientId: 1,                 // 患者ID（URL参数，后端会重新设置）
  doctorId: 16,                 // 医生ID（可选，后端会从排班表查询）
  typeId: 1,                    // 挂号类型ID（必填）
  registrationNo: "20251120161001",  // 挂号单号（可选，后端可生成）
  registerTime: "2025-11-20 16:10:01",  // 挂号时间（可选，后端使用服务器时间）
  status: 1,                    // 状态：1-已预约，0-候补（可选，后端会设置）
  priceOriginal: 50.00,         // 原价（可选，后端会从挂号类型表查询）
  actualPrice: 50.00,           // 实付价（可选，后端会根据患者类型重新计算）
  isAdd: 0                      // 是否加号：0-正常号，1-加号（必填）
}
```

### 后端处理流程

1. **数据验证**：检查必填字段
2. **查询排班信息**：从 `doctor_schedule` 表获取医生ID、科室ID、已用号源数
3. **检查重复挂号**：查询 `registration_record` 表，防止同一患者重复预约同一排班
4. **查询挂号类型**：从 `registration_type` 表获取价格信息
5. **检查号源**：比较 `used_quota` 和 `daily_quota`
6. **查询患者信息**：从 `patient` 表获取患者类型（学生/教职工）
7. **计算实际价格**：
   - 学生：使用 `student_price`
   - 教职工：使用 `staff_price`
   - 其他：使用 `price_original`
8. **生成挂号单号**：如果前端未传递，后端生成（格式：`YYYYMMDD + 科室ID + 序号`）
9. **插入挂号记录**：写入 `registration_record` 表
10. **更新排班**：`used_quota = used_quota + 1`
11. **创建消息**：在 `message_log` 表创建"预约挂号成功提醒"消息

### 3. **号源状态计算**

通过计算属性实时计算每个时段的可用状态：

```javascript
const slotStatus = computed(() => {
  // 1. 过滤匹配日期和挂号类型的排班
  const daySchedules = schedules.value.filter(s => {
    const dateStr = s.schedule_date?.substring(0, 10)
    const typeId = s.type_id
    return dateStr === appointmentDate.value && 
           Number(typeId) === Number(selectedType.value.typeId)
  })
  
  // 2. 按时段分组，计算剩余号源
  daySchedules.forEach(schedule => {
    const slotKey = timeSlotReverseMap[schedule.time_slot]
    const remaining = schedule.available_quota ?? 0
    result[slotKey] = {
      exists: true,
      available: remaining > 0,
      remaining
    }
  })
  
  return result
})
```

## 📨 消息通知系统

### 1. **消息通知概览**

消息通知系统在挂号流程中自动创建和推送消息，包括：
- **挂号成功通知**：支付成功后立即创建
- **就诊提醒**：就诊前一天和前一小时自动提醒
- **候补通知**：加入候补队列和候补转正通知
- **退号通知**：取消挂号时的通知

---

### 2. **消息类型说明**

| 消息类型 | 说明 | 创建时机 | 标题 |
|---------|------|---------|------|
| `APPOINTMENT_SUCCESS` | 预约挂号成功提醒 | 挂号记录创建成功后立即创建 | "预约挂号成功提醒" |
| `APPOINTMENT_REMINDER` | 就诊前一天提醒 | 就诊前一天早上8点（定时任务或查询时检查） | "就诊前一天提醒" |
| `APPOINTMENT_ONE_HOUR` | 就诊前一小时提醒 | 就诊前一小时（定时任务创建） | "就诊前一小时提醒" |
| `APPOINTMENT_WAITING_JOIN` | 加入候补队列通知 | 加入候补队列时创建 | "已加入候补队列" |
| `APPOINTMENT_WAITING_SUCCESS` | 候补转正通知 | 候补转正时创建（可能是加号或退号释放） | "候补挂号成功" / "加号成功" |
| `APPOINTMENT_CANCEL` | 退号通知 | 取消挂号时创建 | "退号成功" |

**加入候补队列方法 (`addToWaitingQueue`)**：
```java
private Result<String> addToWaitingQueue(Long scheduleId, Long patientId, Long recordId) {
    // 1. 创建候补队列记录
    WaitingQueue queue = new WaitingQueue();
    queue.setScheduleId(scheduleId);
    queue.setPatientId(patientId);
    queue.setRecordId(recordId); // 关联挂号记录ID
    queue.setQueueTime(LocalDateTime.now());
    
    // 2. 计算候补排名（当前最大排名 + 1）
    Integer maxRank = registrationMapper.selectMaxQueueRank(scheduleId);
    queue.setQueueRank(maxRank != null ? maxRank + 1 : 1);
    queue.setStatus(0);
    
    // 3. 插入候补队列
    waitingQueueMapper.insert(queue);
    
    // 4. 创建"加入候补队列"消息
    createWaitingJoinMessage(scheduleId, patientId, queue);
    
    return Result.OK("已加入候补队列");
}
```

**创建加入候补消息 (`createWaitingJoinMessage`)**：
```java
private void createWaitingJoinMessage(Long scheduleId, Long patientId, WaitingQueue queue) {
    // 1. 查询排班、患者、医生、科室信息
    DoctorSchedule schedule = registrationMapper.selectScheduleById(scheduleId);
    Patient patient = patientMapper.selectById(patientId);
    Doctor doctor = doctorMapper.selectById(schedule.getDoctorId());
    Department department = departmentMapper.selectById(schedule.getDeptId());
    
    // 2. 获取用户ID（优先从Token获取，否则从患者表获取）
    String currentUserId = resolveCurrentUserId();
    String userId = currentUserId;
    if (StringUtils.isBlank(userId) && patient != null && patient.getUserId() != null) {
        userId = String.valueOf(patient.getUserId());
    }
    
    // 3. 创建消息对象
    Message message = new Message();
    message.setUserId(userId);
    message.setAppointmentId("WAITING_" + queue.getQueueId()); // 使用队列ID作为标识
    message.setMessageType("APPOINTMENT_WAITING_JOIN");
    message.setTitle("候补排队成功提醒");
    message.setCreatedTime(LocalDateTime.now());
    message.setIsRead(false);
    
    // 4. 组装消息内容（JSON格式）
    Map<String, Object> payload = new HashMap<>();
    payload.put("patient_card_no", patient.getOutpatientNumber());
    payload.put("patient_name", patient.getPatientName());
    payload.put("doctor_name", doctor.getDoctorName());
    payload.put("department_name", department.getDeptName());
    payload.put("appointment_time", buildAppointmentTime(schedule.getScheduleDate(), schedule.getTimeSlot()));
    payload.put("waiting_rank", queue.getQueueRank()); // 候补序号
    payload.put("waiting_join_time", DATE_TIME_FORMATTER.format(queue.getQueueTime())); // 加入时间
    payload.put("hospital_remark", "您已成功加入候补队列，系统将在有号源时自动通知");
    
    message.setContent(objectMapper.writeValueAsString(payload));
    
    // 5. 保存消息
    messageService.save(message);
}
```

// 1. 退号时自动触发候补补位
public void autoFillFromQueue(Long scheduleId, int fillCount) {
    // 查询候补队列（按排名排序）
    List<WaitingQueue> queueList = waitingQueueMapper.selectQueueByScheduleId(scheduleId);
    
    for (WaitingQueue queue : queueList) {

**创建候补转正消息 (`sendWaitingSuccessMessage`)**：
```java
private void sendWaitingSuccessMessage(
    RegistrationRecord candidate, 
    WaitingQueue queue, 
    boolean isAddQuota  // 是否为加号场景
) {
    // 1. 查询挂号详情
    RegistrationDetailDTO detail = registrationMapper.selectRegistrationDetail(candidate.getRecordId());
    
    // 2. 获取用户ID
    String userId = resolveUserIdForMessages(detail);
    
    // 3. 创建消息对象
    Message message = new Message();
    message.setUserId(userId);
    message.setAppointmentId(String.valueOf(candidate.getRecordId()));
    message.setMessageType("APPOINTMENT_WAITING_SUCCESS");
    
    // 4. 根据是否为加号场景，设置不同的标题
    if (isAddQuota) {
        message.setTitle("加号成功提醒");
    } else {
        message.setTitle("候补挂号成功提醒");
    }
    
    message.setCreatedTime(LocalDateTime.now());
    message.setIsRead(false);
    
    // 5. 组装消息内容
    Map<String, Object> payload = new HashMap<>();
    payload.put("patient_card_no", detail.getPatientCardNo());
    payload.put("patient_name", detail.getPatientName());
    payload.put("doctor_name", detail.getDoctorName());
    payload.put("department_name", detail.getDepartmentName());
    payload.put("appointment_time", buildAppointmentTime(detail.getScheduleDate(), detail.getTimeSlot()));
    payload.put("waiting_rank", queue.getQueueRank()); // 原候补序号
    payload.put("waiting_join_time", DATE_TIME_FORMATTER.format(queue.getQueueTime())); // 加入候补时间
    payload.put("promote_time", DATE_TIME_FORMATTER.format(LocalDateTime.now())); // 转正时间
    payload.put("source_type", isAddQuota ? "add_quota" : "normal_waiting"); // 来源标识
    
    // 6. 根据场景设置不同的备注
    if (isAddQuota) {
        payload.put("hospital_remark", "管理员已为您增加号源，候补已转为正式号，请按时就诊");
    } else {
        payload.put("hospital_remark", "候补已转为正式号，请按时就诊");
    }
    
    message.setContent(objectMapper.writeValueAsString(payload));
    
    // 7. 保存消息
    messageService.save(message);
}
```

#### 3.2 就诊提醒消息创建

**创建时机**：
1. **立即创建**：如果预约日期是明天且当前时间>=8点，创建挂号时立即创建
2. **查询时创建**：用户打开消息中心时，如果满足条件（明天预约+当前时间>=8点），自动创建提醒
3. **定时任务**：每天早上8点执行，为所有明天的预约创建提醒

**涉及文件**：
- `MessageServiceImpl.java` - `listMessagesByUserId()` 方法
- `AppointmentReminderTask.java` - 提醒任务类

**详细流程**：

```java
// 1. 检查当前时间是否 >= 8点
if (LocalTime.now().isBefore(LocalTime.of(8, 0))) {
    return; // 未到8点，不创建提醒
}

// 2. 计算明天的日期
LocalDate tomorrow = LocalDate.now().plusDays(1);

// 3. 查询所有明天的预约记录
List<RegistrationDetailDTO> tomorrowRegistrations = 
    registrationMapper.listRegistrationsByDate(tomorrow);

// 4. 通过预约成功消息匹配当前用户
for (RegistrationDetailDTO reg : tomorrowRegistrations) {
    // 查询该预约的成功消息
    Message successMsg = messageMapper.selectOne(
        new QueryWrapper<Message>()
            .eq("appointment_id", reg.getRecordId())
            .eq("message_type", "APPOINTMENT_SUCCESS")
    );
    
    // 如果成功消息中的 user_id 与当前用户匹配，则创建提醒
    if (successMsg != null && successMsg.getUserId().equals(userId)) {
        // 检查是否已有提醒消息
        Message existingReminder = messageMapper.selectOne(
            new QueryWrapper<Message>()
                .eq("appointment_id", reg.getRecordId())
                .eq("message_type", "APPOINTMENT_REMINDER")
        );
        
        // 如果没有，创建提醒消息
        if (existingReminder == null) {
            createReminderMessage(reg, userId);
        }
    }
}
```

### 7. **消息提醒机制**

#### 7.1 提醒创建时机

1. **立即创建**（创建挂号时）
   - 条件：预约日期是明天 && 当前时间 >= 8点
   - 执行：`appointmentReminderTask.checkAndCreateImmediateReminder(detail)`

2. **查询时创建**（打开消息中心时）
   - 条件：预约日期是明天 && 当前时间 >= 8点 && 还没有提醒消息
   - 执行：`MessageServiceImpl.listMessagesByUserId()` 中调用 `checkAndCreateRemindersForUser(userId)`

3. **定时任务创建**（每天早上8点）
   - 执行：`AppointmentReminderTask.createRemindersForTomorrow()`
   - 为所有明天的预约创建提醒消息

#### 7.2 提醒消息类型

- **`APPOINTMENT_REMINDER`**：就诊前一天提醒（创建时间固定为当天8点）
- **`APPOINTMENT_ONE_HOUR`**：就诊前一小时提醒（定时任务创建）

### 9. **消息通知完整流程**

#### 10.1 正常挂号消息流程

```

  ↓

  ↓

  ↓

  ↓
检查是否需要立即创建提醒
  ↓
（如果需要）创建提醒消息（APPOINTMENT_REMINDER）
  ↓
用户打开消息中心
  ↓
前端请求消息列表 API
  ↓
后端检查并创建缺失的提醒
  ↓
返回消息列表给前端
  ↓
前端渲染消息列表
  ↓
用户点击消息
  ↓
跳转到消息详情页
  ↓
前端请求消息详情 API
  ↓
后端返回消息详情
  ↓
前端解析并展示消息内容
```

#### 10.2 候补挂号消息流程

**场景1：加入候补队列**
```
用户选择加入候补
  ↓
前端调用 createRegistration(record, patientId, true)
  ↓
后端检测号源已满
  ↓
创建候补挂号记录（status=0）
  ↓
调用 addToWaitingQueue() 加入候补队列
  ↓
计算候补排名（当前最大排名+1）
  ↓
插入候补队列记录
  ↓
调用 createWaitingJoinMessage() 创建消息
  ↓
查询排班、患者、医生、科室信息
  ↓
获取用户ID（从Token或患者表）
  ↓
创建消息（APPOINTMENT_WAITING_JOIN）
  ↓
消息内容包含：候补序号、加入时间等
  ↓
保存消息到数据库
  ↓
用户打开消息中心查看"已加入候补队列"消息
```

**场景2：候补转正**
```
退号释放号源 / 管理员加号
  ↓
触发 autoFillFromQueue() 自动补位
  ↓
查询候补队列（按排名排序）
  ↓
找到排名第一的候补记录
  ↓
更新挂号记录状态（status: 0 → 1）
  ↓
更新排班已用号源（used_quota + 1）
  ↓
调用 sendWaitingSuccessMessage() 创建消息
  ↓
判断转正来源（isAddQuota：加号 or 正常退号）
  ↓
查询挂号详情
  ↓
创建消息（APPOINTMENT_WAITING_SUCCESS）
  ↓
根据来源设置不同标题和备注
  - 加号：title="加号成功提醒"，source_type="add_quota"
  - 退号：title="候补挂号成功提醒"，source_type="normal_waiting"
  ↓
消息内容包含：候补序号、加入时间、转正时间等
  ↓
保存消息到数据库
  ↓
用户打开消息中心查看"候补挂号成功"或"加号成功"消息
  ↓
前端根据 source_type 显示不同文案
```

### 11. **消息通知注意事项**

1. **用户ID匹配**：消息的 `user_id` 必须与登录用户的 `user_id` 匹配
2. **消息内容格式**：`content` 字段存储为JSON字符串，前端需要解析
3. **提醒创建时机**：提醒消息在特定时间点创建，不是实时创建
4. **消息去重**：创建提醒前会检查是否已存在，避免重复创建
5. **消息排序**：消息列表按 `created_time` 降序排列（最新的在前）
6. **未读状态**：新创建的消息默认 `is_read = 0`（未读）

## ⚠️ 注意事项

1. **就诊卡前置条件**：挂号前必须创建就诊卡，否则会提示跳转到创建页面
2. **重复挂号检查**：同一患者不能重复预约同一排班（status != 3）
3. **号源实时性**：排班信息需要实时查询，避免号源超售
4. **候补队列**：号源已满时可选择候补，状态为 `status: 0`
5. **价格计算**：后端会根据患者类型重新计算实际价格，前端传递的价格仅供参考
6. **消息通知**：挂号成功后会自动创建消息，用户可在消息中心查看
